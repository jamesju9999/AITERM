# 系統連線第三期：定時任務

日期：2026-11-17　狀態：使用者授權照建議做到完成
前置：第一期（系統連線）、第二期（配方）已合併 master。

## 目標
到時間自動讓 AI 在某個系統上完成一段目標（例如「每天 09:00 匯出昨天的待處理訂單」），不需要人坐在前面。

## 設計
- **任務**：屬於一個系統，有名稱、目標（一段自然語言）、週期。週期沿用 Agent 協作定時器已有的純函式
  （`tasks::schedules::{Spec, validate, due}`）：每天（多個時間點）、每週（星期幾＋時間）、固定間隔（每 N 分鐘，最短 5 分鐘，可限時段）。時間一律本地時區。
- **誰來做事**：用 Claude Code 的無人模式。排程器到點時執行
  `<設定的 claude 指令> -p <提示> --mcp-config <檔> --allowedTools mcp__aiterm-systems --output-format text`，
  MCP 設定指向本機的系統連線端點（第一期那個）。因此 AI 能用的只有 `sys_*` 工具，且**每個動作仍走寫入閘門**。
- **提示**：告訴 AI 要在哪個系統（id）、目標是什麼，並要求：先 `sys_list` 與 `sys_recipe_list`；有適用的配方就用配方；
  每個動作都要帶「讀：／寫：」意圖；被閘門拒絕就不重試、直接回報；最後用一句話回報結果。
- **沒人在時的核准**：逐次核准的系統，沒人按核准 5 分鐘後自動拒絕（第一期行為），任務會以失敗收場並寫明原因。
  任務表單會提醒：只有「依規則」或「全部自主」的系統適合無人執行，並在系統是「只讀」或「逐次核准」時顯示警示。
- **不堆疊**：上一輪還在跑就跳過這一輪（記為「跳過」）。App 沒開時錯過的時間不補跑。
- **逾時**：單次執行上限 30 分鐘，逾時終止。
- **失敗處理**：連續失敗 3 次自動停用並通知（事件 `systems://job-disabled`）；成功一次就歸零。系統被停用時任務也不跑（記為「跳過」）。
- **結果**：每次執行留一筆記錄（開始／結束時間、狀態、claude 最後輸出的摘要，上限 4000 字），每個任務保留最近 20 筆。
- **手動執行**：畫面上「現在執行」，走同一條路徑。

## 儲存
`systems.db`：`system_jobs(id, system_id, name, goal, kind, spec_json, enabled, created_ms, last_fired_ms, fail_streak, disabled_reason)`、
`system_job_runs(id, job_id, started_ms, finished_ms, status, summary)`。

## 畫面
系統連線頁每個系統多一個「定時任務」：列表（名稱、週期文字、狀態、最近一次結果）、新增／編輯表單、啟用／停用、現在執行、刪除、查看最近執行記錄。

## 不做
Windows 工作排程器式的開機喚醒、錯過補跑、任務之間的相依、通知中心整合（只送事件，畫面顯示停用原因）。

## 測試
- 純函式：週期是否到點（沿用既有測試）＋任務的「該不該跑」判斷（停用、系統停用、正在執行）、提示內容、claude 引數組成。
- 儲存：建立／更新／刪除、連續失敗自動停用、執行記錄保留 20 筆。
- 執行器用假 `claude` 腳本：確認傳入的引數、提示內容、輸出摘要、非 0 結束碼＝失敗、逾時被終止。
- 端到端（真 Chrome、假 claude）：排程到點→假 claude 以 HTTP 呼叫端點的 `sys_*` 工具→假網站的寫入被閘門依權限處理。
