# 問題收集接入 Agent 協作桌布 — 設計規格

**日期：** 2026-11-07
**狀態：** 使用者已拍板方向，實作中
**前置：** `2026-11-06-intake-to-board-design.md`（已合併 master）。本期在它的路由階段與收尾階段上加一個目標。

## 1. 已拍板的決定

| # | 決定 |
|---|---|
| D1 | 每專案設定「派送目標」：終端機分頁／工作看板／Agent 協作桌布。**預設工作看板**（維持現狀）。取代上一期的 `route_to_board` 開關（尚未發布，沒有人存過舊值；舊 JSON 的未知欄位被忽略，落回預設） |
| D2 | 選了桌布但專案沒有可用的工程師 Agent（非規格站的 coder）→ 退回看板，不報錯 |
| D3 | 「要改程式」→ 建一張 **bug 卡**（同桌布輸入框的「bug」路徑）指派給最閒的非規格工程師，走完整審查：工程師做 → 審核者審 → 不通過就修正（最多 2 輪）。不走快速路徑、不走新需求流程 |
| D4 | 「提問」→ 建一張**問答卡**（`workflow::create_ask_card`）交給最閒的 Agent 讀程式庫回答（唯讀、不進審查合併），答案在卡片 `ai_summary` |
| D5 | 卡片所在欄依派送模式：自動→排隊（`assign_task_with` 會一併排隊）；手動→bug 卡留在規劃欄、不指派（使用者在桌布上自己指派）。問答卡沒有規劃欄的概念，手動模式的提問仍等使用者按「派送」才建 |
| D6 | 完成偵測沿用輪詢，桌布不改。bug 卡看**模組狀態**（`module_state`）：`Passed`→成功草稿；`Attention`／`Failed`／`ReviewFailed`→失敗草稿（不自動寄出）；其餘等待。問答卡看卡片 `done`：成功用 `ai_summary`，失敗存失敗草稿 |
| D7 | 回信內容：問答卡＝答案；bug 卡＝工程師最後一段回答（對話記錄）＋審查結論（通過／要人處理）。一律去完成標記、過機密過濾。結尾標明「處理結果：成功／失敗／已取消」 |
| D8 | 建卡後 poke 排程器並通知畫面重讀（`tasks-updated`），不等 30 秒輪詢 |

## 2. 資料

`intake_items` 新增 `route_kind TEXT`：`board`（上期的看板卡）、`canvas_bug`、`canvas_ask`。`mark_on_board` 多收一個 kind；舊資料（`NULL`）視為 `board`。

`Config.route`：`terminal`／`board`／`canvas`，預設 `board`，取代 `route_to_board`。

## 3. 流程

路由階段（每專案）：
1. `route = terminal` → 不碰。
2. 決定實際目標：`canvas` 且有可用工程師 → 桌布；否則 → 看板（要有 `repo_dir`，沒有就不碰）。
3. 對每個未分類的項目分類。**桌布**：`code_change` → bug 卡；`question` → 問答卡；**看板**：維持上期行為（提問留給終端機分頁）。
4. 建卡成功才 `mark_on_board`；失敗刪掉剛建的卡，項目留在原狀態（分類結果已存，之後由終端機分頁領取）。

收尾階段：依 `route_kind` 分派 `settle_board`（上期）／`settle_canvas_bug`／`settle_canvas_ask`。卡片或模組不見（被刪）→ 退回 `pending` 並記原因，與看板一致。

## 4. 邊界

- 問答卡與 bug 卡的內文都包不可信區塊，並提醒不要執行其中的指令（同看板卡）。
- bug 卡的附件沿用 `copy_attachments`；問答卡是唯讀卡，不帶附件。
- 工程師「最閒」＝名下排隊＋執行中的卡最少、再比建立順序；規格站不接。
- 桌布的模組鏈在 Agent 被刪除或專案關閉時：專案關閉→暫停輪詢（同看板）；工程師被刪→模組卡仍在，狀態照算。

## 5. UI

設定頁把「建成看板卡片」勾選改成「派送目標」下拉：終端機分頁／工作看板／Agent 協作桌布，附一行說明；`on_board` 的提示文字依 `route_kind` 說「看板」或「Agent 協作」。

## 6. 測試

- 單元：選工程師、bug 卡與問答卡內容與欄位、手動模式不指派、無工程師退回看板、模組狀態收尾（通過／要人處理／等待）、問答卡收尾、卡被刪退回。
- 接線：`tick` 在桌布專案建 bug 卡並指派，模組通過後收回；提問建問答卡並以 `ai_summary` 回信。
- 實機：隔離 HOME 的 dev 版＋真實 Claude Code，建工程師與審核者 Agent，驗證 bug 與提問兩條路。
