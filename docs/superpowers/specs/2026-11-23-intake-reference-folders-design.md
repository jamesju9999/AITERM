# 問題收集：每個管道各自的「參考資料夾」

## 1. 目標

派送任務給 AI 時，在提示詞裡告訴它「回答前先去這些資料夾找相關資料」。資料夾由使用者在設定頁**每個管道各自**指定（信箱、Telegram、LINE、網頁表單各一份清單），診斷模式與可改檔案模式都適用。

**範圍外**：向量檢索／知識庫整合（另案）、硬性限制 AI 只能讀哪些檔案（做不到，見 3.5）、系統連線派送目標。

## 2. 已拍板的決定

- 做法是**提示詞指示**：AI 自己用讀檔、搜尋工具去找；AITerm 不建索引、不預先擷取內容。
- **允許絕對路徑**（使用者決定）。也接受 `~` 開頭（展開成家目錄）與相對路徑（相對於專案／工作資料夾，提示詞會註明）。
- 每個管道一份清單，預設空。清單空就完全不加這段提示詞（行為與現在一致）。

## 3. 設計

### 3.1 設定

`Config.channel_refs: ChannelRefs { email, telegram, line, web: Vec<String> }`（舊設定缺欄位時為空）。`Config::refs_for(source)` 依題目來源（`email`／`telegram`／`line`／`web`）取清單，不認得的來源回空。存的是使用者輸入的原樣（去頭尾空白、略過空字串、去重）。

### 3.2 提示詞

`dispatcher::refs_note(paths)`（空清單回空字串）：

> 【參考資料夾】回答前請先到下列資料夾尋找相關資料（用 Read、Grep、Glob 讀取；pdf 可直接讀），依資料回答並註明引用的檔名；找不到就明說不知道，不要猜。這些資料夾只供參考，不要修改裡面的檔案：
> - `<路徑>`（相對路徑會註明「相對於專案資料夾」）

加到三種派送：

- 終端機分頁：附在 `build_prompt` 之後（完成偵測用的標記在第一行，不受影響）。
- 看板：`route_item`（提問卡與要改程式的卡都附）。
- 桌布：`route_canvas_ask`、`route_canvas_bug`。

三處都在函式內依 `item.project_id` 與 `item.source` 自己載入設定取清單，不改函式簽章。系統連線路線不附。

### 3.3 檢查資料夾（`intake_check_folders`）

設定頁用來告訴使用者「這個路徑能不能用」。對每個路徑回傳：是否存在、是否為資料夾、**Claude Code 讀得到的檔案數**（md、txt、rst、pdf、csv、json、yaml、yml、xml、html、htm、log）、**讀不了的 Office 檔數**（doc、docx、docm、odt、ppt、pptx、pps、xls、xlsx、xlsm、ods、odp、rtf、epub）。遞迴掃描、略過 `.` 開頭的項目、最多看 5000 個項目（超過標示「已截斷」）。`~` 展開；相對路徑相對於專案資料夾（有的話）。純檔案系統操作，三平台通用。

### 3.4 畫面

每個管道分頁「處理方式」下方新增「參考資料夾」：清單（路徑＋狀態）、輸入框加「加入」、「選擇資料夾…」（原生選取器，只在按下時開，不在掛載時開）、每列「移除」。狀態：✓ 可讀檔 N 個；⚠ 不存在；⚠ 有 M 個 Office 檔 Claude Code 讀不了（建議轉成 md／pdf）；⚠ 沒有可讀的檔案。說明文字寫明限制（3.5）。

### 3.5 限制（寫在說明文字裡）

1. **工作目錄以外的資料夾可能要許可。** 依對 Claude Code 的了解，它預設只能讀工作目錄內的檔案；目錄外的路徑會要求許可，終端機分頁可能因此停在等許可。解法：把資料夾放進專案資料夾底下，或在專案的 Claude Code 設定預先允許。**尚未實機驗證。**
2. Claude Code 不能直接讀 Office 檔（docx、pptx、xlsx…）；md、txt、pdf 可以。
3. 這是**提示詞層級**，不是強制：AI 仍可能讀到專案資料夾裡的其他檔案。要硬性限制，需要知識庫檢索（另案）。
4. 資料夾很大時，AI 自己翻找會比較慢、比較耗額度。

### 3.6 安全

路徑由使用者設定，視為可信；不經由題目內容傳入。提示詞只列路徑，不展開內容。資料夾內容對 AI 而言是參考資料，不是指令；提示詞已要求不修改。

### 3.7 測試

- 設定：預設空、舊設定相容、`refs_for` 四個來源與未知來源、正規化（空白、去重）。
- `refs_note`：空清單回空字串；有清單列出每個路徑；相對路徑有註記。
- 派送：終端機提示詞、看板卡（提問卡與要改程式卡）、桌布問答卡與 bug 卡，在設了清單時含該段，沒設時沒有；不同管道各用各的清單。
- `intake_check_folders`：不存在、是檔案不是資料夾、可讀與 Office 計數、隱藏項目略過、截斷、`~` 展開。
- 前端：加入／移除／選擇資料夾寫進該管道的設定、狀態標示。

## 4. 實作紀錄

- 已完成：後端 `cargo test -p app --lib intake::` 213 條全過；前端 `npm run test` 全過；`npx tsc -b` 與我改的檔案 ESLint 乾淨。
- 與設計不同或補充：
  - **新增「所有管道共用」清單**（使用者追加）：`ChannelRefs.shared`，實際生效＝共用的＋該管道自己的（去重，共用的在前）；畫面上放在「接收路徑」卡片最下方，說明寫明客戶（外部）管道也會用到，所以共用清單只放可對外的資料。
  - 終端機派送的提示詞是在 `runtime` 呼叫端組出來的（`build_prompt` 之後附上），需要真實 PTY，沒有單元測試；`refs_note` 與 `build_prompt` 各自有測試，看板與桌布派送有接線測試。
  - 「新增資料夾」按鈕文字不能叫「加入」，會跟白名單的「加入」撞名。
  - **未實機驗證**：資料夾在專案資料夾以外時 Claude Code 是否真的會要求許可、終端機分頁會不會因此停住；原生資料夾選取器。
