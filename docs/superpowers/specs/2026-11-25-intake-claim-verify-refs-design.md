# 問題收集領取處理：做完後的驗證與本機參考資料夾

日期：2026-11-25　狀態：已核可

## 目標

成員在自己電腦領取 server 的題目、用 Claude Code 處理時，補上兩個與桌面版本機派送對齊的能力：

1. 「要改程式」的題目做完後，自動驗證並把結果帶回 server。
2. 領取者的 Claude Code 能讀到該專案的參考資料夾（server 設定的是 server 上的路徑，領取者的電腦通常沒有）。

## 驗證

- **派工前**：在領取者終端機分頁的工作資料夾記下 git HEAD（沿用 `verify::snapshot`）。server 沒標示題目種類（`kind` 為空）時一律當成「要改程式」，與本機的保守做法相同；`kind = question` 不驗證。
- **完成後**：用專案設定的 `verify_command` 與 `verify_timeout_secs`（server 設定，管理員在設定頁已有欄位），在領取者的工作資料夾執行 `verify::verify`；報告先去敏再附到回覆最後。
- **交回 server**：結果一律是草稿（server 本來就不自動寄出）。驗證沒過**不阻擋**交回，問題清單標示「驗證未通過」，提醒審稿的人。
- **API**：`POST /v1/items/{id}/result` 多收選填的 `verification`（文字）與 `verified`（布林），存進既有欄位；舊版 AITerm 不傳也照常運作。回傳的題目資料帶這兩個欄位。

## 參考資料夾

- 在領取者**自己的 AITerm**（連線模式）設定頁新增「我電腦上的參考資料夾」，每個 server 專案一份，只存在自己的電腦，任何成員都能設。
- 分兩組，與桌面版一致：共用、僅內部；外部客戶的題目只帶共用那組（沿用 `refs_for`）。
- 派工時照本機做法附進提示詞（`dispatcher::refs_note`）；不存在的資料夾略過並在畫面提示。
- 設定頁註明：server 上設定的路徑不會帶給領取者。

## 不做

server 傳檔案、自動同步資料夾、依題目種類分別設驗證指令、驗證未通過時阻擋交回。

## 驗證計畫

自動測試（server 結果 API 新欄位、領取流程帶驗證與參考資料夾、舊客戶端相容）＋真實 Claude Code 的端到端演練。
