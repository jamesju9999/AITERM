# 問題收集：LINE 群組（讀所有訊息、新問題自動開題）

## 1. 背景與目標

客戶都在 LINE **群組**裡跟我們的人員溝通（見 `docs/superpowers/specs/2026-11-23-intake-line-design.md` 的範圍外項目）。目標：

1. AI 讀取已授權群組裡的**每一則**訊息並在本機保存，作為前情。
2. 客戶**不用 @**，新的問題就會自動進問題清單；被 @ 的訊息則立即開題。
3. 回覆直接傳回群組；沿用既有的等級、派送、自動寄出、診斷／可改檔案規則。

**範圍外**：圖片與檔案、AnyDesk 連線、AI 在沒有開題的情況下主動對客戶發言。

## 2. 已拍板的決定

- 只讀**白名單內**的群組（`line:C…`）；白名單外的群組不保存任何訊息，只記下編號供使用者加入。
- 新問題自動開題（使用者決定）。開題不等於發言：是否自動回覆由群組的等級與「自動寄出回覆」決定；客戶群組建議設為「外部」＝手動核准後才派送。
- 預設值（使用者沒反對，可在設定頁調）：保存 30 天；前情取最近 30 則且 24 小時內。

## 3. 設計

### 3.1 來源與編號

- LINE 編號：`U`＝使用者、`C`＝群組、`R`＝多人聊天室，皆為前綴字母加 32 位十六進位。白名單與 `sender` 存 `line:<小寫編號>`；`reply_target` 把第一個字元還原成大寫。直接貼編號也可（同 `line:` 前綴省略規則，擴及 `C`、`R`）。
- 群組項目的 `sender` 是群組代號（`line:c…`），`source` 仍是 `line`。

### 3.2 資料（`intake.db` 新增兩張表，`line_store.rs`）

- `line_messages(chat, msg_id, user_id, name, text, ts, outgoing, handled)`，`UNIQUE(chat, msg_id)`：群組逐則訊息。`outgoing=1` 是 AI／人員從 AITerm 回到群組的內容。`handled=1` 表示這則已被某一題涵蓋或已被判定不用處理。
- `line_unknown(id, kind, name, count, first_seen, last_seen)`：還沒在白名單的來源（只記編號、名稱、次數，**不存訊息內容**）。
- 保存天數到期自動刪除（每次 webhook 處理後與每輪 tick 順手清）。

### 3.3 webhook 處理（`line_server`）

事件取 `source.type` ∈ {user, group, room}，另處理 `join`（機器人被拉進群組，記到 `line_unknown`）。

- 一對一：行為不變。
- 群組／聊天室，訊息文字：
  1. 群組代號不在任何啟用 LINE 的專案白名單 → 記入 `line_unknown`，丟棄（`not_allowed`）。
  2. 在白名單（同時在多個專案 → `ambiguous_project`）→ 存入 `line_messages`（以 `msg_id` 去重）。
  3. 訊息有 @ 到機器人（`mention.mentionees[].isSelf`）→ **立即開題**（見 3.4）。
  4. 沒 @ → 留給 3.5 的自動開題。
- 成員顯示名稱以 LINE 成員資料取得並快取；取不到用簡短編號。

### 3.4 開題內容

`body` ＝ 前情（該群組最近 30 則、24 小時內、不含本次，最舊的先被截掉，總長上限）＋這次的訊息。外部內容仍整段包在 `build_prompt` 的不可信區塊裡。`message_id` ＝ `line:<chat>:<訊息 id>`（自動開題用該批第一則）。開題後，該批涵蓋到的訊息標 `handled`。

### 3.5 新問題自動開題（`runtime::line_triage`，在既有 3 秒 tick 裡）

對每個啟用「自動開題」的專案、每個白名單群組：

1. 取 `handled=0` 的**客戶**訊息（排除 `outgoing`、排除我方人員）。我方人員＝該專案白名單裡以 `line:U…` 加入的使用者（等級內部）。
2. 等**靜默**：最後一則未處理訊息已超過 90 秒沒有新訊息，才處理（讓客戶把話講完、把多則合成一題）。
3. 若在這批第一則之後，**我方人員或 AI 已有發言** → 人員已在處理，把這批標 `handled`，不開題。
4. 若該群組已有未結束的項目（pending／queued／running／on_board／draft）→ 不再開新題，標 `handled`（限制：之後的補充不會自動併入那一題，需要時請 @ 一次）。
5. 呼叫 AI 判斷這批是不是**新的問題或請求**（閒聊、道謝、「好的」不是）。AI 失敗或逾時時**當成問題**（寧可多開不漏）。判斷結果為否 → 標 `handled`；為是 → 開題（3.4）。

### 3.6 回覆

`send_reply` 的 `line` 分支不變（push 到 `reply_target(sender)`，群組代號同樣適用）；成功後若是群組，把回覆內容記進 `line_messages`（`outgoing=1`），下次前情就含 AI 自己說過的話，也讓 3.5 的第 3 點能辨識「AI 已回」。

### 3.7 設定與畫面

- `Config.line_auto_open`（預設 true）、`Config.line_retention_days`（預設 30，全域，0＝不保存）。
- LINE 分頁：保存天數、「客戶沒 @ 時自動開題」開關、**「最近出現但未加入白名單的來源」**清單（群組／使用者，名稱、次數、最後時間，按鈕「加入白名單」，等級可選，也可「忽略」）。說明文字寫明：白名單內群組的訊息會保存在本機 N 天，只有開題時才會把前情送給 AI。
- 問題清單沿用既有的管道標籤；群組來的項目，提問者顯示「群組名稱」。

### 3.8 安全與隱私

- 白名單外的群組**不存訊息**。
- 簽章驗證不變；陌生來源不回覆。
- 前情是不可信資料，進提示詞前與其他來源一樣包在不可信區塊；回覆照舊先過 `redact`。
- 保存天數有上限刪除；使用者可把天數設 0 完全不保存（此時沒有前情、也無法自動開題，只剩被 @ 的單則開題）。
- 群組內所有成員的對話都會被保存，**部署前要在群組公告**（寫在設定頁說明）。

### 3.9 測試

- `line_source`：編號（U／C／R）與前綴省略、群組事件解析（@ 與否、join、room、時間戳）、`route_group`（白名單外不存、存且不開題、@ 開題含前情、去重、歧義、前情範圍與截斷）。
- `line_store`：寫入去重、前情查詢、保存期限清理、未知來源計數。
- `line_server`（HTTP＋wiremock）：群組訊息存入但不開題、@ 開題、未知群組只記編號、join 事件、名稱查詢與快取。
- `line_triage`：靜默等待、客戶批次合併、我方人員已回則不開題、已有未結束項目則不開題、AI 判否不開題／判是開題／失敗仍開題。
- 前端：未知來源清單的加入與忽略、保存天數與自動開題設定寫入。
