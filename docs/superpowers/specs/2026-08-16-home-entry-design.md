# AITerm 首頁入口 — 設計

日期：2026-08-16
狀態：待使用者核可

## 問題

AITerm 目前沒有首頁。啟動時 `/` 直接就是 `TerminalApp`，`restoreSessionTabs()` 無聲還原上次的分頁，使用者落在最後一個分頁裡。這造成三件事：

1. **11 種分頁沒人發現。** 終端機、資料庫、VCS、知識庫、Loop Studio、文件轉換等入口全部藏在 `NewTabPicker` 那個小選單裡，不點「＋」就看不到。
2. **背景狀態看不見。** AI 用量與配額要點進「設定 → 用量」才看得到；進行中的 agent mission 只有企業任務會浮出一個面板（`TerminalApp.tsx:522` 有 `enterpriseTask` 過濾），一般任務的進度只存在該分頁內部。
3. **重開之後接不回去。** 分頁雖然還原了，但「上次做到哪、在哪個目錄」沒有留下——`aiSummary` 只存在記憶體，`aiterm_last_cwd` 只留全域最後一個目錄。

## 範圍

**含：**

- 側邊欄固定一顆「首頁」按鈕，啟動時停在首頁
- 首頁四個區塊：分頁大圖入口、上次工作（分頁卡片 + 最近專案目錄）、AI 用量與配額、進行中的任務
- 首頁的自然語言輸入框，由 AI 判斷該開哪一種分頁
- 為了「上次做到哪」而必須新增的持久化：每分頁的 cwd、每分頁的 AI 摘要、最近專案目錄清單

**不含（各自是獨立子系統，之後各走一輪設計）：**

- 自動收信／看信／回信（`MailView` 的 IMAP 後端已在，但分頁在 `NewTabPicker/index.tsx:65` 被註解隱藏；回信、附件解析尚未實作）
- 登入外部系統寫每日日報（外部系統自動化）
- OS 層活動記錄（前景應用、視窗標題、閒置時間、行事曆、瀏覽器分頁）
- 待辦清單／任務排程引擎
- 首頁的自訂版面（區塊順序、顯示與否）

原始需求是「自動化使用者的所有工作」。那涵蓋信箱協定、外部系統自動化、作業系統監控三個彼此無關的技術棧，不可能在一份 spec 裡收斂。這份 spec 只做入口本身，並把自動化能力設計成之後可以掛上來的東西。

## 決策紀錄

以下四項是使用者在 brainstorm 中明確選定的，其中兩項與作者的建議相反，實作時不要「順手改回來」：

| 決策 | 選定 | 作者原本建議 |
|---|---|---|
| 首頁在結構裡是什麼 | **A：側邊欄固定按鈕** | B：首頁是一種分頁類型 |
| 「上次工作」怎麼呈現 | **分頁卡片 + 最近專案目錄，兩者都要** | 擇一 |
| 輸入框行為 | **AI 判斷該開哪種分頁** | 未表態 |
| 第一版內容 | 分頁入口 + 上次工作 + 用量 + 進行中任務 + 輸入框 | 同 |

## 架構

### 首頁不是分頁

首頁是側邊欄上一顆固定按鈕，位置在 logo / Collapse 底下、`.aiterm-tabbar-tabs` 之外。它：

- 關不掉
- 不參與拖曳排序（`onReorder` 只作用在 `tabs` 陣列上，首頁不在裡面）
- 不佔 `Ctrl+1~9` 的編號
- 側邊欄收合成 48px 時仍在，只剩圖示

`TerminalApp` 新增一個 `homeActive` 布林狀態：

- `true`：內容區顯示 `HomeView`，**所有分頁沿用既有的 `visibility: hidden` + `pointer-events: none` 手法隱藏**
- 點任何分頁 → `false`；點首頁按鈕 → `true`
- 初始值 `true`（開 app 先看到首頁）；`restoreSessionTabs()` 行為完全不變，分頁照樣還原，只是不在前景

**分頁絕對不能改成卸載。** xterm.js 在元素沒有尺寸時 resize 會直接爆掉，這是 `CLAUDE.md` 明文記載的地雷，也是現有程式碼刻意用 `visibility` 而非條件渲染的原因。

### 快捷鍵

回首頁用 `Ctrl+0`。**不可以用 `Ctrl+H`**——那在終端機裡是 backspace（`^H`），會破壞終端機輸入。`Ctrl+1~9` 已經是分頁切換，`0` 接在後面且未被 xterm 使用。

鍵盤處理沿用 `TerminalApp` 既有的 capture-phase `keydown` 監聽器（`TerminalApp.tsx:332` 的 `handleKeyDown`），不要另外掛一組。修飾鍵沿用該處既有慣例：只看 `e.ctrlKey`，三個平台一致（macOS 也是 Ctrl 而非 Cmd）。

`Ctrl+0` 在 Windows/Linux 的 webview 是「重設縮放」，所以務必 `preventDefault()`；macOS 的重設縮放是 `Cmd+0`，不衝突。

## 四個區塊與資料來源

| 區塊 | 資料來源 | 新增工作 |
|---|---|---|
| 分頁大圖入口 | `NewTabPicker` 的項目定義 | **必須共用同一份定義**，不可以複製第二份清單——兩份一定會分岔 |
| 進行中的任務 | 已在 `tabs` 裡：`agentProgress`（由 `TerminalView` 的 `onAgentProgress` 寫入，`TerminalApp.tsx:499`） | 近乎零成本。**不要沿用 `TerminalApp.tsx:522` 那個 `enterpriseTask` 過濾**，首頁要顯示所有進行中的任務 |
| AI 用量與配額 | `useProviderQuota` + `ipc/usage` 的本地累計 | 只是換個地方顯示 |
| 上次分頁做到哪 | `aiSummary` 已在 `tabs`（`TerminalApp.tsx:504`） | **它只存記憶體，重開 app 是空的**——要顯示就得寫進 `SavedTab` |
| 每分頁的工作目錄 | `getSessionCwd` 輪詢已存在（`TerminalView.tsx:185`） | 目前只寫一個全域的 `aiterm_last_cwd`，要改成每分頁一份 |
| 最近的專案目錄 | 同上 | 新的一份清單：路徑去重、依最後使用時間排序、**最多保留 10 筆**，超過就丟掉最舊的 |

成本集中在最後兩列：**「進行中任務」和「用量」幾乎是免費的，真正的工作是把現在被丟掉的 cwd 與摘要留下來。**

### 持久化的變更

`SavedTab`（`TerminalApp.tsx:38`）目前是 `Pick<Tab, "title" | "type" | "dbConnectionId">`，需要擴充 `cwd` 與 `aiSummary`。兩者都是選填：`cwd` 只對終端機分頁有意義，`aiSummary` 只有跑過指令的分頁才有。首頁的分頁卡片對沒有這些欄位的分頁就只顯示標題與類型，不顯示空白欄位。

兩個必須守住的相容性條件：

1. **舊的 localStorage 內容必須還能讀。** `restoreSessionTabs` 已經包在 try/catch 裡，但新欄位一律當成選填，缺欄位不能讓整份還原失敗（失敗會讓使用者的分頁全部消失）。
2. **不要動 `aiterm_last_cwd` 既有的語意。** 它是新終端機分頁的起始目錄來源（`TerminalView.tsx:971`），與這裡要新增的「每分頁 cwd」是兩件事。相關的 CWD 同步邏輯很脆弱，改動時要一併確認 FileExplorer 的路徑同步沒有壞。

## 輸入框的 AI 路由

把「AITerm 有哪些分頁類型、各自能做什麼」當成清單餵給 AI，要它回傳 `{ type, params }`。沿用使用者目前選定的 provider（`listProviders`），不另外挑模型。

三個防呆，缺一個這個功能就會變成惹人厭的東西：

1. **輸出限制。** AI 只能回既有 `TabType` 之一。清單外的值、空回應、解析不出 JSON，一律當成失敗，不可以照單全收去開一個不存在的分頁類型。
2. **猜錯要能反悔。** 不做「開之前先確認」的兩步流程（那會失去「一句話就開始」的意義）。改成直接開，並在新分頁上顯示一條可關閉的提示：「AI 判斷你要的是 X 分頁 — 不對？換成…」。開錯的成本因此只是關掉一個分頁。
3. **降級路徑。** AI 未設定、網路失敗、逾時（`AiError` 已是以 `kind` 區分的 discriminated union，直接分流）一律退回「開終端機分頁 + 把整句話當成 agent mission 的目標」，走既有的 `initialMission` 管道。**輸入框永遠有反應，不會因為 AI 掛掉就變成死的。**

## 錯誤處理

| 情況 | 行為 |
|---|---|
| AI 未設定／網路失敗／逾時 | 降級為終端機分頁 + agent mission（見上） |
| AI 回了清單外的分頁類型 | 同上，當成失敗處理 |
| 用量／配額抓不到 | 該區塊顯示「無法取得」，不影響首頁其他區塊 |
| 最近專案目錄已不存在 | 仍然列出，點下去才提示找不到；不在首頁載入時逐一檢查檔案系統（會拖慢啟動） |
| 舊版 localStorage 缺少新欄位 | 當成選填，其餘照常還原 |

## 測試

- **AI 路由的解析與防呆**（清單外的值、空回應、各種 `AiError` 分流）→ 純函式，Vitest 直接測，不碰網路
- **各區塊的呈現**（沒有進行中任務、用量抓不到、最近專案是空的）→ React Testing Library
- **`SavedTab` 的相容性**：舊格式（缺 `cwd` / `aiSummary`）能正常還原 → 純函式測 `restoreSessionTabs`
- **`homeActive` 的切換與啟動預設**：邏輯要放在可獨立測試的地方，**不要埋進 `TerminalApp` 的 JSX**——`TerminalApp` 在這個 repo 沒有測試 harness（`src/App.test.tsx:6` 把它整支 mock 掉），埋進去就等於測不到

### 測試證明不了、必須手動驗證的

- 在首頁與終端機分頁之間來回切換多次後，xterm 的 resize 不會爆
- 側邊欄收合成 48px 時，首頁按鈕仍可點
- `Ctrl+0` 在終端機分頁有焦點時仍能回首頁，且不會被 xterm 吃掉

## 這個設計不保證什麼

- **不保證 AI 路由猜得準。** 它靠的是防呆與可反悔，不是準確率。若實際使用發現常猜錯，正確的反應是檢討提示詞與分頁類型描述，而不是加上「開之前先確認」——那等於退回沒有 AI 的版本。
- **不保證首頁不會變慢。** 用量與配額是網路請求。首頁必須先畫出來再填資料，不可以等資料到齊才顯示，否則會讓 app 啟動看起來變慢。
- **不做任何自動化。** 這份設計只把資訊集中呈現與提供入口，不會自己去收信、寫日報或執行任何工作。
