# Agent 協作：等你回覆、自主完成與幾個收尾 — 設計

日期：2026-10-16
狀態：使用者要求在 Pomodoro 測試後實作（「現在開始做這些待辦」）

## 實機問題（Pomodoro 測試）

1. 規格撰寫師寫完規格後停下來問「待確認事項」，Agent 協作畫面看不出它在等人，只能自己去翻終端機。
2. 派出去的 Agent 預設會停下來問問題，但自動派工時旁邊通常沒有人。
3. 那張卡是「互動」卡：不會被完成標記結案，要手動標記完成，但 Agent 協作畫面上沒有這個按鈕，也看不出原因。
4. 一鍵 git init 時看板專案資料夾在程式庫裡面，被一起 commit 進去；之後看板每次更新都讓程式庫「有未提交的改動」，合併後無法自動合回。
5. 一輪合併完，各工程師的分支不會更新成整合後的版本；同一專案開新一輪時，工程師會從舊版開始。

## 設計

### 1. 偵測「在等你回覆」（非互動卡）

派工時掛的 Claude Code HTTP hook 改成：
- `Stop`（Claude 結束一輪回覆）→ `/turn-end`
- `PostToolUse`、`UserPromptSubmit` → `/working`（又在動、或使用者回覆了）
- `StopFailure` → `/stop-failure`（額度，不變）

收到 `/turn-end` 後等 8 秒；期間沒有 `/working`、卡片也還沒結案（完成標記會讓卡片結案、解除登記）→ 標記「等你回覆」：
- 記憶體＋新欄位 `tasks.reply_wait_at`；`finish_task` 清掉。
- 等待期間 `monitor` 不做卡住判定（跟等額度一樣）。
- 送 `agent-reply-wait` 事件：前端發系統通知（照「派工完成時通知」的設定）。
- 收到 `/working` 就解除。

### 2. 不要停下來問（非互動的 Agent 卡）

派工提示的角色前綴之後加一段：「這是自動派工，旁邊沒有人會即時回答。遇到不確定的地方，採用最合理的做法，
把假設寫進文件或交件說明的『待確認事項』，然後直接把工作做完，不要停下來詢問。」互動卡不加（本來就是人在旁邊）。

### 3. 互動卡在 Agent 協作畫面

- 執行中的互動卡：Agent 卡上顯示「互動卡：做完請按標記完成」與「標記完成」按鈕（呼叫既有 `tasks_mark_done`）。
- 非互動卡在等回覆：顯示「💬 在等你回覆」，旁邊是既有的「前往分頁」。
- 頂列總覽加「· N 個 Agent 在等你」（等回覆＋執行中的互動卡）。
- 看板卡片（TaskCard）等回覆時，提示改成「💬 在等你回覆」。

### 4. 看板專案資料夾在程式庫裡面

在程式庫的 `.git/info/exclude` 加上看板專案資料夾的相對路徑（已經有就不加）：
- 一鍵 git init：在第一個 commit 之前加（`agents_init_repo` 多帶 `project_id`）。
- 準備 Agent 工作資料夾時也檢查一次（舊專案、或資料夾是之後才搬進去的）。
不在程式庫裡面就什麼都不做。只寫 `.git/info/exclude`（本機、不進版控）。

### 5. 新一輪從整合結果開始

工程師卡（work／fix）開工前，在合併前置之前：協調者最後一次成功合併的結果（合併卡的 `end_sha`）如果還不在
這位工程師的分支上，先 `git merge` 進來（通常是快轉）。衝突 → 還原、派工失敗、工程師暫停（同開工前合併前置）。

## 測試

- Rust：hook 設定的事件對應；`/turn-end` 後 grace 期滿標記、期間 `/working` 或解除登記就不標記；`finish_task` 清 `reply_wait_at`；
  等回覆時 monitor 不判卡住；自主完成說明只加在非互動卡；exclude 只在資料夾位於程式庫內時加、不重複加；
  init 不再把看板資料夾 commit 進去；整合結果合進工程師分支（已包含就不動、衝突還原）。
- 前端：等回覆提示、互動卡的標記完成按鈕、頂列計數、TaskCard 提示、通知事件。
