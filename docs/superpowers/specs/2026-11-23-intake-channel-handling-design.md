# 問題收集：每個管道各自決定「只診斷」或「可改檔案」，清單顯示來源管道

## 1. 目標

- 四個接收管道（信箱、Telegram、LINE、網頁表單）各有一個設定：**只診斷**或**可改檔案**。
- 問題清單每一列顯示這題是從哪個管道來的。

## 2. 決定

- 設定是**每個專案、每個管道一個值**，存在專案設定 `Config.channel_handling`。
- 預設：信箱／Telegram／網頁表單＝**可改檔案**（維持現有行為）；**LINE＝只診斷**（診斷對談是它的用途，也較安全）。舊設定檔沒有這個欄位時用上述預設。
- 兩種處理方式的語意：
  - **可改檔案**：照現有流程。AI 初篩「提問／要改程式」；要改程式的依「派送目標」（看板／桌布／終端機）處理並做修復驗證。
  - **只診斷**：一律視為提問，**不呼叫初篩 AI**；因為是提問，所以不做修復驗證（不會因「沒有檔案變更」被擋成草稿）。派送目標若是看板或桌布，建的是唯讀的問答卡；若是終端機，送進去的提示詞多一段「只診斷、不要修改檔案、不要執行會改變系統的指令」。
- 系統連線路線（`Route::System`）本來就把每題當作在外部系統上完成的事項，不受此設定影響。
- **限制（要老實寫在畫面上）**：終端機路線的「只診斷」是提示詞層級的要求，不是沙箱；該分頁的 Claude Code 若有寫入權限，理論上仍可能不照做。要硬性保證，請讓該分頁以唯讀／計畫模式啟動，或改用看板／桌布的問答卡（卡片本文同樣是要求唯讀）。

## 3. 設計

| 位置 | 變更 |
|------|------|
| `intake/config.rs` | `Handling { Diagnose, Edit }`、`ChannelHandling { email, telegram, line, web }`（有各自預設）、`Config.channel_handling`、`Config::handling(source)`（未知來源當可改檔案）。 |
| `intake/runtime.rs` | `classify_item` 先看該題管道的處理方式：只診斷 → 直接回「提問」。終端機派送時把處理方式傳給 `build_prompt`。 |
| `intake/dispatcher.rs` | `build_prompt(item, images, diagnose)`：只診斷時加上唯讀要求段落。 |
| 前端 `IntakeView` | 每個管道分頁加「處理方式」下拉＋一句說明；清單每列加管道標籤（信箱／Telegram／LINE／網頁表單）；詳情的來源標籤改成同一個在地化名稱。 |

## 4. 測試

- 設定：預設值、舊 JSON 缺欄位仍可讀、`handling()` 對四個來源與未知來源。
- `classify_item`：只診斷不需要 AI 就回提問；可改檔案在沒有 AI 時仍退成「要改程式」。
- 接線（`tick`）：同樣的內文，LINE（只診斷）建出的是唯讀問答卡、信箱（可改檔案）建出的是一般卡。
- `build_prompt`：只診斷才含唯讀要求。
- 前端：每個管道分頁的下拉會寫進設定；清單列顯示管道標籤。
