# 問題收集 ④ 領取處理 — 設計

日期：2026-11-24
狀態：使用者選定「手動與自動兩種都要」，其餘依預設實作
上層設計：`2026-11-23-intake-server-design.md`（子專案 ④）

## 問題

連到 server 時，題目只會被收進共用清單，沒有任何人或程式處理。需要讓成員用**自己電腦上的 Claude Code** 處理 server 上的題目，並把結果交回 server。

## 決策

| 決策 | 選定 |
|---|---|
| 觸發 | **兩種都要**：清單上按「我來處理」（手動）；以及「收集中」分頁閒置時自動向 server 領下一題 |
| 可領取的題目 | 狀態是 `queued`（內部題目自動進入；外部題目要先核准）。`pending` 不能領 |
| 領取 | server 上的**原子動作**；同一題同時只有一個人拿得到 |
| 租約 | 領取後 **15 分鐘**有效；處理中每 **2 分鐘**自動續約；逾期由 server 放回 `queued`（成員關機、當機、斷線都靠這個收回） |
| 執行位置 | 領取者自己的電腦：題目與附件下載到本機，丟進他「收集中」的終端機分頁（沿用本機派送的標記、完成偵測、看門狗） |
| 結果 | 分頁裡 Claude Code 的最後回答 → `result` → 題目變成 `draft`，由人看過再用 LINE 送出。**不自動寄出** |
| 失敗 | Claude Code 結束、分頁關閉、取不到回答 → `fail`：回 `pending` 並記原因，不自動重派（與本機一致） |
| 放回 | 領取者或管理員可以按「放回」（回 `queued`）；停止收集、結束 AITERM 時自動放回 |
| 誰看得到 | 所有人在清單看到「處理中：誰」；只有領取者與管理員能放回、交結果 |

## 第一版不做

- 派到看板或 Agent 協作、改程式後的自動驗證與分類（結果一律是草稿，由人把關）。
- server 設定裡的參考資料夾（那是 server 上的路徑）；診斷模式的提示照常帶。
- 外部題目免核准直接領。

## 資料與 API

**題目新增欄位**（可空）：`claimed_by`（成員名稱）、`claimed_at`、`claim_expires_at`；`IntakeItem` 與前端型別同步新增。

| 端點 | 說明 |
|---|---|
| `POST /v1/items/{id}/claim` | 領這一題。成功回題目；不是 `queued` 或已被領走回 `409` |
| `POST /v1/projects/{pid}/claim-next` | 領這個專案最舊的 `queued`；沒有就回 `null` |
| `POST /v1/items/{id}/heartbeat` | 續約；只有領取者可以，回是否成功 |
| `POST /v1/items/{id}/release` | 放回 `queued`；領取者或管理員 |
| `POST /v1/items/{id}/result` | 交結果：`{"reply":"…"}` → `draft`；`{"error":"…"}` → `pending`＋原因；只有領取者 |
| `GET /v1/attachments/{att}/file` | 附件原始內容（要下載到領取者的電腦） |

所有動作寫稽核；回覆內容在 server 端過 `filter::redact`。Server 每 30 秒掃一次，把租約逾期的 `running` 放回 `queued`。

## AITERM 端

- 連到 server 時，終端機工具列的「啟動問題收集」**重新可用**：選 server 的專案，這個分頁就成為那個專案的接收端（登錄在本機的分頁登錄表，專案 id 是 server 的）。
- **手動**：題目詳情在 `queued` 時多一顆「我來處理」→ 找該專案「收集中」且閒置的分頁；沒有就明確告知要先啟動收集。
- **自動**：本機的定時掃描在連線模式下，對每個閒置、Claude Code 在跑的「收集中」分頁，向 server `claim-next`。
- **派送**：用同一份提示詞（`build_prompt`，含診斷模式提示）送進分頁；附件先下載到本機再把本機路徑寫進提示詞。
- **續約**：有領取中的題目就每 2 分鐘 `heartbeat`；續約失敗（被收回或成員被撤銷）就中止這題並放掉分頁。
- **完成**：沿用 Claude Code 的 Stop hook → `result`。**結束**（session-end、分頁關閉、停止收集）→ `fail` 或 `release`。
- 本機資料庫不存這些題目。

## 已知限制

- 租約逾期收回後，原領取者的 Claude Code 可能仍在跑；他稍後交結果會被 server 拒絕（題目已不是他的），畫面要明說。
- 同一個人同時開多個分頁會各領各的，這是預期行為。
- 沒有「收集中」分頁時，自動領取什麼都不做；手動領取會說明原因。

## 測試

- server：原子領取（兩人同時領，只有一人成功）、不能領 `pending`、租約續約與逾期放回、非領取者不能交結果／續約／放回、管理員可以放回、`result` 後變草稿且回覆已去敏、失敗回 `pending`、附件下載擋路徑穿越、稽核。
- 端到端（真的 server＋真的 Client）：A 領取後 B 領同一題得 409；A 交結果後清單顯示草稿；逾期後 B 可以領。
- AITERM：連線模式下的分頁登錄、`tick` 自動領取（假的 Claude Code 分頁狀態）、手動領取沒有分頁時的錯誤、完成與結束的分流、續約失敗中止。
- 前端：「我來處理」按鈕的顯示條件、顯示「處理中：誰」、領取失敗訊息；工具列按鈕在連線模式下可用。
