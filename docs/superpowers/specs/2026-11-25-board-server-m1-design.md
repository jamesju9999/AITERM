# 工作看板 server 化 M1：共用看板卡片

日期：2026-11-25　狀態：待核可

## 背景與範圍

看板與 Agent 協作 server 化（⑤）拆成三段：**M1 共用看板卡片**（本 spec）、M2 共用 Agent 協作、M3 卡片在 server 執行。
M1 只做「大家看到同一份看板、成員領取後在自己電腦執行」，沿用問題收集 server 已驗證的做法（server 存資料、Client 用遠端模式、領取＋租約＋續約）。

**M1 包含**：一般工作卡片（`card_kind = work`）的共用：建立、編輯、移動欄位與排序、標籤、附件、封存、刪除；成員領取後在自己電腦派工（用現有的終端機派工），完成結果回寫 server；即時更新；多人同時編輯的衝突處理。
**M1 不含**：Agent 協作畫布（Coder／Reviewer／Orchestrator、編制、定時器、記事本、規格卡）、卡片在 server 執行、worktree 合併的遠端操作。這些在遠端模式下對應的入口隱藏或停用，並註明「下一階段」。

## 核心問題：卡片裡哪些是共用的、哪些只屬於一台電腦

`tasks` 表現在把兩類資料混在一起。M1 把它們分開：

| 共用（存 server） | 只在領取者的電腦（本機） |
|---|---|
| 標題、內容、狀態、排序、標籤、`parallel_ok`、`interactive`、結果（`outcome`）、AI 摘要、錯誤訊息、建立／派送／完成／封存時間、附件、留言 | 終端機分頁 `tab_id`、對話紀錄 `transcript_path`、`session_id`／`session_path`、worktree 路徑與分支、`start_sha`／`end_sha`、橋接設定 |

- **專案對應**：卡片的 `project_dir` 是各台電腦不同的路徑。server 的看板專案沿用問題收集的專案（`projects`，含 `work_dir`）；每位成員在自己的 AITerm 為每個 server 專案設定「我電腦上的專案資料夾」（只存本機，與問題收集的「我電腦上的參考資料夾」同一套做法）。沒設定就不能領取。
- **領取與執行**：成員在 `queued` 欄按「我來處理」＝向 server 領取（原子；同一張只有一人領到；租約 15 分鐘、處理中每 2 分鐘續約，逾期自動放回）。領到後，AITerm 在本機建一張**影子卡片**（存在本機看板資料庫，不顯示成第二張卡），用現有的派工流程執行（終端機分頁、worktree、對話紀錄都留在本機）；影子卡片的狀態變化（執行中、完成、失敗與其結果、摘要）由 AITerm 回寫到 server 的那張卡。看板上大家看到的是 server 的卡片與狀態。
- **本機操作仍只有領取者能做**：看對話紀錄、續聊、停止、推一把、合併 worktree 這些依附在本機執行的操作，只在領取者的電腦、對自己領取的卡片可用；別人看到的是狀態與結果。

## Server

- **資料**：新表 `board_cards`（上表「共用」欄位＋`project_id`、`created_by`、`claimed_by`、`claimed_at`、`claim_expires_at`、`version`）、`board_attachments`（沿用問題收集附件的儲存與大小限制）、`board_messages`（留言）。放在 server 的資料庫，進入 server 的資料庫升級流程。
- **API**（`/v1/board/...`，成員皆可，建立與編輯記稽核）：列出卡片（含附件與留言）、建立、更新、移動（欄位＋排序）、標籤、封存／取消封存／全部封存、刪除、附件上傳與下載、留言；領取（原子）、續約、放回、交結果／回報失敗、回寫狀態（執行中、摘要）。
- **併發**：每張卡有 `version`，更新要帶讀到的版本，過期回 409，Client 重新載入並提示（不靜默覆蓋別人的修改）；移動排序以「放在某張之後」表達，避免多人同時拖曳時順序錯亂。
- **即時更新**：沿用既有的 WebSocket 變動通知。
- **權限**：成員可建立、編輯、移動、領取；刪除與全部封存限卡片建立者或管理員。

## Client（AITerm）

- 連到 server 時，看板走遠端模式：看板指令（`tasks_list`、建立、更新、移動、標籤、附件、封存、刪除、留言）對應 server API，沿用問題收集的 `remote_or!` 做法，**畫面元件不改資料來源以外的邏輯**。
- 領取與影子卡片：新增 `board_claim`、`board_release`；影子卡片與 server 卡片的對應存在本機（`remote_cards`）；派工流程完成時的既有回呼（`finish_task`／狀態更新事件）多一個「若是影子卡片就回寫 server」的掛點。
- Agent 協作入口在遠端模式隱藏。

## 實作順序（各自可驗收）

1. **Server 資料與 API**＋API 測試（含領取競爭、版本衝突、權限、附件）。
2. **Client 遠端模式的看板讀寫**＋測試（既有的看板畫面不動，指令走 server）。
3. **領取與影子卡片執行**＋測試（假 `claude`；租約逾期收回；回寫）。
4. **畫面細節**：專案資料夾對應設定、領取按鈕、衝突提示、遠端模式下停用的入口。
5. **端到端**：真實 Claude Code 領一張卡、執行、結果回寫並被另一位成員看到。

## 風險

- `tasks/` 約 2.3 萬行與看板前端約 1.9 萬行；遠端模式只換資料來源，但影子卡片的回寫掛點要穿過現有派工與完成流程，是最容易出回歸的地方，每步都要完整跑既有測試。
- 同一張卡的本機狀態（worktree、對話紀錄）離線或換電腦後無法接手；M1 接受，領取逾期放回後由下一位重新開始。
- 舊的本機看板資料不會自動上傳到 server；提供「把本機看板專案複製到 server」留待後續。

## 不做

Agent 協作、server 執行、跨電腦接手同一張卡的本機狀態、本機看板資料的自動遷移。
