# Agent 協作：專案的團隊編制切換

日期：2026-10-20　狀態：已實作（計畫：`docs/superpowers/plans/2026-10-20-agent-canvas-team-formations.md`）

## 問題

一個專案在不同階段需要不同的角色組成。以舊系統轉換為例：先盤點（需求分析師＋研究工程師＋彙整），再轉換（需求分析師＋移植工程師＋驗收者），最後量產實測。現在每個專案只有一張桌布、一組團隊，要換組成只能「清空團隊」再「套用範本」，有三個問題：

1. 清空會丟掉每位 Agent 自己的設定：資料庫技能、自訂技能、模型、CLI、提示詞的修改、在桌布上的位置。之後要回到上一個階段，得重新設定一次。
2. 團隊範本存在這台機器（localStorage），不跟著專案走；換一台電腦（例如在 Windows 上接手）就沒有。
3. 有人還在工作就不能清空，只能自己盯著等做完。

## 決定

維持「一個專案一張桌布、同一時間只有一組團隊」，新增**團隊編制**：一個專案可以存好幾組編制，依階段切換。不做多組團隊同時運作，原因是：

- 一個團隊只能用一個程式庫，協調者只合併同一個程式庫的分支；兩組同時改同一個程式庫會有兩位協調者各自合併主線。
- 審核者、協調者、驗收者每個專案只能各有一位，品管流程是照這個設計的。
- 不同組成的需要實際上是依先後順序出現的（盤點 → 轉換 → 實測），很少同時。

| 情況 | 做法 |
|---|---|
| 同一個程式庫、不同階段要不同角色 | 同一個專案，切換編制（本規格） |
| 同一個程式庫、同時有不同類型的工作 | 同一組團隊放不同專長的工程師，用卡片指派 |
| 不同程式庫、無關的工作 | 分成不同專案（現況） |

## 編制裡存什麼

一組編制 = 名稱＋一份 Agent 清單。每位 Agent 存：

- 種類、名稱、角色、提示詞前綴、模型、CLI、是否產出規格
- 資料庫技能、自訂技能（目前存在 `agents` 資料列上，清空就消失）
- 在桌布上的相對位置

**不存**在編制裡、留在專案上的，換編制時都保留：

- 卡片（模組庫、看板、已完成的歷史）、活動記錄
- 程式庫（專案資料夾）、專案簡介、參考資料、額度設定（`project_settings`）

前一個階段的產出（例如 `docs/inventory/*.md`）已經合併在程式庫裡，下一個階段的 Agent 直接讀得到。

## 儲存

存在專案自己的 `tasks.db`，跟著專案資料夾走（換電腦、在 Windows 上打開都在）：

```sql
CREATE TABLE IF NOT EXISTS formations (
  id TEXT PRIMARY KEY NOT NULL,
  name TEXT NOT NULL,
  agents TEXT NOT NULL,        -- JSON：上面列的每位 Agent 欄位
  sort_order REAL NOT NULL,
  updated_at INTEGER NOT NULL
);
```

`project_settings`：

- `active_formation`：目前桌布對應的編制 id
- `pending_formation`：等待切換的目標（見下）；沒有就不存

**舊專案**：第一次打開時，桌布上有 Agent 而沒有任何編制的話，用目前的團隊建立一組名為「預設」的編制並設為目前編制。

**自動保存**：目前的編制不需要手動存。桌布上的變動（新增或刪除 Agent、改設定、裝技能、拖曳位置）在切換前一刻寫回目前的編制。只在切換時寫一次，不必每次變動都寫。

## 切換

### 沒有人在工作：直接切換

1. 把目前桌布寫回目前的編制。
2. 移除桌布上全部 Agent，沿用 `delete_all_agents`：排隊中的模組退回模組庫，已完成卡片的歷史保留。
3. 依目標編制建立 Agent。程式庫用專案的程式庫，位置從桌布左上開始擺。
4. `active_formation` 改成目標，活動記錄寫一筆「切換編制：盤點 → 轉換」。

步驟 2、3 任一步失敗：已移除的不還原，但 `active_formation` 不改。畫面顯示錯誤，目前桌布維持原樣，使用者可以再切換一次，因為步驟 1 已經存下原本的編制。

### 有人在工作：做完再換

「有人在工作」= 有執行中的卡片，或排隊中的審查、修正、合併、驗收卡（一張模組還在品管流程裡）。

- 切換時列出還在忙的 Agent，讓使用者選「做完後切換」或「取消」。
- 選了「做完後切換」：
  - 寫入 `pending_formation`。
  - 排程器**不再開始新的模組卡**，但品管流程照跑：審查、退回修正（最多 2 輪）、合併、驗收。已經開工的模組會完整走完。
  - 排隊中、還沒開工的模組卡在切換時退回模組庫（同清空）。
- 排程器每輪檢查：有 `pending_formation` 且已經沒人在工作，就執行上面的切換步驟。
- 桌布上方顯示「等目前的工作做完後切換到『轉換』」，旁邊有「取消切換」。

不做「強制立即切換」。要立即換，使用者先手動停止執行中的卡片，就會落到直接切換。

## 畫面

**桌布上方的編制選單**（放在「團隊範本」左邊）：

```
[ 編制：盤點 ▾ ]  [ 團隊範本 ]  [ 清空團隊 ]
   ├ ✓ 盤點
   │   轉換
   │   實測
   ├ ──────────
   │   新增空白編制…
   │   把目前團隊另存成新編制…
   │   重新命名目前編制…
   └   刪除編制…（不能刪目前的）
```

- 選另一組 = 切換（上一節的流程）。
- 新增空白編制：建立並切換過去，桌布變空，接著用「團隊範本」或手動放 Agent。
- 專案只有一組編制時，選單還是顯示，讓使用者知道有這個功能。

**團隊範本對話框**：「套用」維持現在的行為，把 Agent 加到目前桌布，也就是目前編制。另外新增「套用成新編制」：用範本建立一組新編制並切換過去，名稱預設為範本名稱。不用先清空，原本的團隊會留在原來的編制裡。

**清空團隊**：維持現狀，只清目前編制的桌布；目前編制變成空的。

## 不在這次範圍

- 多組團隊同時運作。
- 編制在專案之間共用：要共用就用團隊範本，存在本機。
- 卡片綁定編制（例如「這張卡只給轉換編制做」）。目前退回模組庫的卡由使用者在新編制裡指派，或由協調者依規格拆。

## 待驗證（結果）

- 已完成卡片指向已刪除的 Agent：原本活動記錄會顯示「?」。已處理：刪除 Agent 時把名稱與種類記進 `retired_agents`，活動記錄找不到桌布上的 Agent 時改用它，名稱與角色色點都保留。
- 移除的 Agent 的工作副本和分支不刪（沿用「不自動清理」的決定）。這次不處理，切換幾次之後磁碟用量會增加。

## 測試

後端（`cargo test --workspace --no-fail-fast`）：

- 編制的新增、列出、改名、刪除；不能刪目前的編制。
- 切換：目前桌布寫回目前編制，包含資料庫技能、自訂技能和位置；移除後依目標建立；`active_formation` 更新；卡片退回模組庫、已完成的保留。
- 有人在工作時切換被拒並列出名字；`pending_formation` 期間不開始新模組卡，但審查、修正、合併卡照跑；流程走完後自動切換。
- 舊專案第一次打開時自動建立「預設」編制；沒有 Agent 的專案不建。
- 切回上一組編制時，技能與設定跟離開前一樣。

前端（Vitest）：

- 編制選單的顯示、切換、新增、另存、改名、刪除。
- 有人在工作時出現「做完後切換」，等待中顯示提示與「取消切換」。
- 範本對話框的「套用成新編制」。
- i18n：zh-TW 與 en 都有字串（比對 `localeSources`）。
