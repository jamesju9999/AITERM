# 敏感資訊遮罩與提示詞助手 設計

日期：2026-10-07
前置：`2026-10-06-goal-milestones-design.md`（畫面歷史、里程碑）。

## A. 敏感資訊遮罩

### 為什麼

建議、里程碑「檢查進度」會把終端機畫面（目前那一屏最多 8000 字元，加上較早畫面最多約 9000 字元）送給使用者設定的
AI 供應商。畫面裡可能有金鑰、token、密碼、私鑰、連線字串。畫面歷史把這個暴露面放大了，這是現有功能的缺口。

### 做什麼

- `src/lib/redact.ts`：`redactSecrets(text) → { text, count, kinds }`。純函式、可重複套用（遮罩後再遮不會再變、不會重複計數）。
- 預設**開啟**，側欄「⋯」選單可關閉，偏好存 `localStorage`（`aiterm-suggest-redact`）。
- 凡是**從終端機取得、要送給 AI 的文字**都先遮罩：產生建議的目前畫面與較早畫面、里程碑檢查進度的目前畫面與較早畫面、
  提示詞助手參考的畫面。使用者自己輸入的文字（目標、潤飾草稿、助手的需求）不遮罩——那是使用者主動寫的。
- **先遮罩、再截斷**：截斷若從 token 中間切開，會留下一段沒被遮的殘片。所以流程是 遮罩完整畫面 → 再截尾／套預算。
- 側欄在產生後顯示一行「已在送出前遮罩 N 處疑似敏感資訊」，讓使用者看得到、可以信任。
- 畫面歷史在記憶體裡仍存原文（不持久化），遮罩只發生在「送出」那一刻。

### 規則（保守：寧可漏遮也不要把正常文字遮成亂碼）

| 類型 | 規則 |
|------|------|
| 私鑰區塊 | `-----BEGIN … PRIVATE KEY-----` 到 `-----END … PRIVATE KEY-----`（含多行；沒有結尾時遮到文字結束） |
| 已知格式的 token | AWS `AKIA…`/`ASIA…`、GitHub `ghp_/gho_/ghu_/ghs_/ghr_/github_pat_`、Slack `xox[abprs]-`、Anthropic `sk-ant-`、OpenAI／類似 `sk-…`（≥20 字）、Google `AIza…`、npm `npm_…`、JWT（`eyJ…eyJ…簽章`） |
| HTTP 認證 | `Authorization: Bearer|Basic|Token <值>`、單獨的 `Bearer <長字串>` |
| 網址內嵌帳密 | `scheme://user:password@host` → 只遮 password |
| 名稱含敏感字的賦值 | 名稱**以**這些字結尾：`password`／`passwd`／`pwd`／`secret`／`secret_key`／`token`／`api_key`／`access_key`／`private_key`／`client_secret`（`tokenizer`、`author` 這類不算；單獨的 `auth` 太容易誤判，不收），後接 `=` 或 `:`（含 JSON 的 `"password": "…"`、`export X_TOKEN=…`），值長度 ≥ 6 才遮；`true`／`false`／`null`／`none`／空值、`<…>`／`${…}`／`$VAR`／`your_…`／`xxx…`／`****` 這類佔位不遮 |

遮罩後的文字保留名稱，例如 `password=[已遮罩]`、`Authorization: Bearer [已遮罩]`，AI 仍看得懂「這裡有一個密碼」。遮罩標記本身不帶類型（類型只回傳給呼叫端，目前只用來計數）。

### 明確限制（要寫進回報）

- 這是規則比對，**不是保證**。自訂格式的密鑰、沒有敏感字眼的賦值、被換行切碎的 token 可能漏掉；
  所以側欄的說明文字不可以寫「已保證安全」，只寫「會嘗試遮罩」。
- 不遮 IP、主機名稱、使用者名稱、專案程式碼本身。

## B. 提示詞助手

### 做什麼

側欄新增可收合的「提示詞助手」區塊（目標與里程碑之下、建議之上）：

1. 使用者用一句話寫粗略需求（例如「幫我把登入改成 REST」）。
2. 按「AI 改寫成提示詞」→ AI 依需求、**大目標與焦點里程碑（若有）**、**目前畫面（已遮罩，最多 4000 字元）**，
   改寫成一則清楚具體、可直接貼給 AI 工具的提示詞，顯示在可編輯的框裡。
3. 使用者可編輯，按「填入」（只填入、不按 Enter）或「填入並送出」；也可「重新改寫」或「清除」。

### 規則

- AI 只改寫，不新增使用者沒要求的需求；資訊不足處用 `〈…〉` 標出待補，不編造路徑或名稱。
- 回覆只要提示詞本身；清理 code fence 與外層引號；上限 2000 字元。
- 獨立串流 id `prompt-assist-<sessionId>`，不進 Ask AI 對話。單一請求、重複點擊保護、目標或分頁改變時取消與丟棄過期回應、
  卸載時中止——沿用目標潤飾與里程碑的做法。
- 結果**不會自動填入**：使用者按了才動終端機。
- 草稿與結果只在記憶體，不持久化。

## 測試重點

- `redact`：每條規則至少一個「該遮」與一個「不該遮」的反例；多行私鑰；沒有結尾的私鑰；重複套用結果不變；計數正確；
  密鑰被截斷點切開時，因為先遮罩再截斷而不會殘留。
- 整合：產生建議與檢查進度的請求內容**不含**原始密鑰、含遮罩標記；關閉設定時送原文；遮罩 N 處的提示出現與消失。
- 提示詞助手：請求內容、清理、不自動填入、填入／送出的呼叫、錯誤、過期回應、重複點擊、卸載中止。
- 每個測試要證明會紅；用突變驗證（拿掉遮罩、改成先截斷再遮罩、拿掉過期丟棄）。

## 不做

- 持久化助手的草稿；多輪對話式的助手；遮罩使用者自己輸入的文字；保證不外洩。
