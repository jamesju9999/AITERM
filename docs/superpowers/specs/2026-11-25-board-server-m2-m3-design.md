# 看板 server 化 M2＋M3：共用 Agent 協作，並在 server 無頭執行

日期：2026-11-25　狀態：S1～S5 已實作並實機驗證；S6 評估後只做了「server 驗證」與「額度續跑」，其餘不適合 server（見下方「S6 結論」）

## 範圍的老實說明

使用者選了完整版：Agent 協作（Coder／Reviewer／Orchestrator）資料多人共用，編排引擎也能在 server 無頭執行。
現有編排約 8 千行（`tasks/workflow`、`scheduler`、`agents`…）、29 張資料表、約 55 個畫布指令，且直接讀寫本機資料庫與終端機。這是數週以上的工程，**不在一個工作階段內做完**。因此拆成下面的階段；每個階段結束都有自動測試與實機驗證，沒做到的階段在更新說明裡如實標示「尚未支援」，不假裝完成。

## 階段（依序做，各自可交付）

| 階段 | 內容 | 驗收 |
|---|---|---|
| **S1 共用資料** | server 存 Agent、卡片的 Agent 欄位（`agent_id`、`card_kind`、`module_id`、`review_of`、`verdict`、`review_reasons`、`depends_on`、`start_sha`／`end_sha`）、專案簡介與記事本；API 與版本衝突沿用 M1 | API 端到端測試 |
| **S2 畫布遠端模式** | 連到 server 時，畫布（Agent 節點、卡片、簡介、記事本）讀寫 server；畫布元件不改 | AITerm 端對應層測試＋實機看到共用畫布 |
| **S3 server 無頭編排核心** | server 的編排迴圈：對有 Agent 的專案，把待派送的 Coder 卡派給閒置 Coder，用 `claude -p` 在每個 Agent 專屬的隔離 worktree 執行；做完建立 Reviewer 卡，Reviewer 用 `claude -p` 輸出審查結論（pass／fail＋理由）；fail 退回 Coder 修正（最多 2 輪）；全部模組通過後，產生待合併分支，**管理員核准才合併** | 假 `claude` 驅動的自動測試＋真實 Claude Code 端到端 |
| **S4 Orchestrator** | 規格卡由 Orchestrator 拆成實作卡（沿用現有的計畫格式），依賴順序派工 | 同上 |
| **S5 定時器** | 每天／每週／間隔建一輪卡片，**只由 server 觸發一次**（多人連線不會重複觸發） | 同上 |
| **S6 其餘** | 驗收者（Verifier）、額度用完續跑、詢問人類、編制切換、技能…逐項評估，不保證納入 | — |

## 設計原則

- **單一事實來源**：連到 server 時 Agent 協作的資料與狀態只在 server；本機不再有第二份。離線時畫布停用（唯讀顯示最後一次內容）。
- **誰執行**：卡片指定「在 server 執行」或「由成員領取」。server 執行走 ③ 的執行器（`claude -p`、最小環境、逾時、並行上限），成員領取沿用 M1 的影子卡片。
- **安全**：server 執行的改動一律在隔離 worktree 與專屬分支；合併進專案要管理員核准，審查通過也不例外；外部客戶來源的卡片不進編排。
- **編排狀態機**：把 `workflow` 的「模組狀態」「審查鏈」「修正輪數」改成不依賴 Tauri／PTY 的純函式與 trait（資料層用 server 的資料庫），桌面版與 server 共用同一份邏輯，避免兩套行為分歧；桌面版本機模式不改變行為（每步完整跑既有測試）。
- **多人編輯**：沿用卡片 `version` 衝突偵測；Agent 與記事本也各有版本。

## 風險

- 編排邏輯抽出共用最容易造成桌面版回歸：每個抽出的函式先用現有測試固定行為再搬。
- `claude -p` 的輸出格式（審查結論 JSON）要用真實 Claude Code 驗證，不能只靠假腳本。
- 長時間執行、server 重啟時的恢復：先支援「重啟後把處理中的卡片放回」，不做中途接續。

## 本次不做

Agent 之間的即時對話（`tell_agent`）、桌布的視覺化新功能、跨專案編排。


## 實作結果（2026-11-26）

- S1 共用資料、S2 畫布遠端模式、S3 無頭編排核心、S4 Orchestrator 拆解、S5 定時器：已完成，都有自動測試（假 claude）與真實 Claude Code 端到端，並從 AITerm 畫布實機驗證。
- 與原規劃的差異：編排狀態機是 server 自己的一份（`aiterm-intake-core::orchestration`），**沒有**把桌面版 3676 行的 `workflow` 抽成共用——風險太高，桌面版維持原狀；只有定時器的週期規則（`Spec`／`due`）搬到 core 共用。

## S6 結論

| 項目 | 結果 | 原因 |
|---|---|---|
| Server 驗證（跑專案驗證指令、結果給審核者） | 已做 | Coder 在 `claude -p` 裡多半沒有權限執行測試，由 server 代跑才有實證 |
| 額度用完續跑 | 已做 | 無人值守時額度用完不該讓整輪失敗 |
| 驗收者（Verifier） | 不做 | 要實際操作應用程式畫面，server 無頭環境沒有 |
| 詢問人類 | 不做 | `claude -p` 非互動，沒有中途提問的管道 |
| 編制切換 | 不做 | 桌面版的「一專案多組編制」對 server 的單一編排沒有意義 |
| 技能（資料庫／自訂／系統連線） | 不做 | 屬於各台電腦的環境，S1 設計原則就排除 |
