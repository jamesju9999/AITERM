# 系統連線：「請 AI 操作」與事後確認存成配方

日期：2026-11-17　狀態：使用者同意此方向

## 問題
目前存配方要靠使用者對 AI 說「請存成配方，參數 …（範例值 …）」，畫面上沒有輸入的地方，也看不到存了什麼。

## 設計
- **請 AI 操作**：系統卡片的第一個分頁。輸入一句話（可 AI 潤飾）→ 送出 → 用跟定時任務同一個執行器（Claude Code 無人模式＋系統連線端點）跑一次。
  同一個系統一次只做一件事（與定時任務、問題收集共用鎖）。
- **自動錄製**：每次一次性執行前清空該系統的操作日誌；執行時後端本來就會記錄成功的動作。執行完回傳 AI 的回報（拿掉「結果：」行）、
  成功或失敗、以及實際做了哪些步驟（工具＋意圖＋讀／寫）。
- **事後確認存成配方**：執行成功且有步驟時，卡片出現「存成配方」區：填名稱（說明可選），並列出系統猜到的**參數候選**
  （輸入的文字、下拉選的值；名稱取自欄位名稱，沒有就 `value1`…），預設全勾、可改名、可取消勾選。按下去存的是剛剛那串步驟，不會多也不會少。
  失敗或被拒絕的那一輪不提供存配方。不存就按「略過」，日誌清空。
- **配方的「執行」**：配方列加「執行」，依該配方的參數出現輸入欄，填完直接重播（走同一把鎖與閘門），結果顯示在列內。
- 安全不變：所有動作仍走寫入閘門與權限模式；配方只存操作，不存放行。

## 後端
- `recipes::suggest_params(steps)`：純函式，從步驟參數找出文字／值候選。
- `SystemsState::journal_steps(system)`、`journal_clear(system)`：日誌檢視與清除。
- 指令：`systems_run_goal(system_id, goal)`、`systems_recipe_save_from_journal(system_id, name, description, params)`、
  `systems_recipe_run(system_id, name, params)`、`systems_journal_discard(system_id)`。

## 測試
- 純函式：候選參數（欄位名稱當參數名、重複值去重、佔位符與過長值不算、下拉的值）。
- 後端端到端（真 Chrome＋假 claude，`--ignored`）：一次性執行→回傳步驟與候選→依候選存配方→用新值重播，網站收到新值；
  系統忙碌時拒絕；失敗的執行不留日誌可存。
- 前端：執行中狀態、結果與步驟、參數候選勾選／改名、存配方呼叫的內容、配方執行的參數欄位。
