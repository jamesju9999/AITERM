# 遠端終端機共享 ②：前端兩側 UI ＋ 區網自動發現 — 設計

日期：2026-08-26
狀態：待使用者核可

## 問題

計畫①（後端傳輸地基）已完成並合併：PTY 輸出 fan-out、授權狀態機、ws 線上格式、TLS ws server、commit-then-reveal 的 4 位驗證碼。整套東西**只能由測試驅動——使用者按不到任何東西**。

本 spec 把它變成人可以用的功能。

## 範圍

**含：**

- 主控端 UI：分享按鈕、分享面板（短碼／位址／觀看者清單）、同意視窗
- 觀看端 UI：連線對話框、`remote-terminal` 新分頁型別
- 區網自動發現（mDNS）：輸入短碼就能找到對方
- 後端補件：Tauri commands、待審請求的事件推送、mDNS 廣播與查詢

**不含：**

- S2（跨機器 presence：誰在線、在做什麼）與 S3（任務分派／交接）——各自留給後續 spec
- 跨網段、VPN、非同區網連線
- 觀看端錄影／回放

## 決策紀錄

以下是使用者在 brainstorm 中明確選定的，實作時不要「順手改回來」：

| 決策 | 選定 | 作者原本建議 |
|---|---|---|
| 計畫②的完成定義 | **連 mDNS 一起做**，輸短碼就能連 | 先做手動位址版，mDNS 留計畫③ |
| 分享入口 | **B：頂部工具列常駐按鈕** | A：分頁右鍵選單（分享本質上針對特定分頁） |
| 同意視窗 | **C：主控端輸入對方唸的 4 位碼** | 同（推薦並採納） |
| 手動位址退路 | **B：找不到時自動展開並說明原因** | 同（推薦並採納） |
| 防火牆 | **事前提醒**，不偵測不阻擋 | 同（推薦並採納） |

**關於 mDNS 提前**：作者原本建議把它留到計畫③，理由是它最容易被環境問題咬，混在一起難分辨問題出在哪。使用者選擇合併後，改用**設計本身**化解這個風險：手動位址永遠是主路徑，mDNS 只是加速器，任何時候壞掉都能退回手動（見「觀看端」）。

## 新元件

前端（都長在既有結構上，不新建框架）：

| 元件 | 責任 |
|---|---|
| `ShareButton` | 頂部工具列，只在終端機分頁顯示 |
| `SharePanel` | 短碼、host:port、防火牆提醒、觀看者清單、停止分享 |
| `ConsentDialog` | 同意視窗——輸入對方唸的 4 位碼 |
| `ConnectDialog` | 觀看端：輸入短碼 → 失敗時展開手動位址 |
| `RemoteTerminalView` | 新分頁型別 `remote-terminal` 的畫面 |

後端：Tauri commands（`share_start` / `share_stop` / `share_approve` / `share_deny` / `share_kick`）、待審請求的事件推送、mDNS 廣播與查詢。

## mDNS：只廣播位址，不廣播內容

**廣播的內容只有「短碼 → host:port」。** 不含分頁標題、不含使用者名稱、不含 cwd。

理由：把分頁標題或使用者名稱廣播出去，等於讓整個辦公室網路知道你正在改哪個專案。觀看端只需要「這組編號在哪台機器」；其餘資訊等連上、對方同意之後才給。

**找到多台機器回應同一組短碼時，直接要求改用手動位址。** 機率是百萬分之一等級，但行為必須定義——不猜、不隨便挑一台，挑錯就是連到陌生人身上。

## 主控端

### 分享面板

按下工具列的分享按鈕後展開：

```
┌─ 分享中 ──────────────────────────┐
│  短碼   5 5 9 2 0 7                │
│  位址   192.168.1.33:47823  [複製] │
│                                    │
│  ⚠️ 系統可能會問你要不要允許連入     │
│     連線，請按「允許」               │
│                                    │
│  觀看者（0）                        │
│  ────────────                      │
│  [ 停止分享 ]                       │
└────────────────────────────────────┘
```

短碼與位址**同時顯示**——對方自動發現失敗時，唸位址即可，不用回頭找。防火牆提醒放這裡，因為系統詢問就是這一刻跳出來的。

分享按鈕在非終端機分頁上隱藏（`ShareButton` 依當前分頁型別決定）。

### 同意視窗

```
┌─ Alice 想連進「Claude Code」──────────┐
│                                        │
│  請對方唸出他畫面上的 4 位數：          │
│         [_] [_] [_] [_]                │
│                                        │
│  ⚠️ 對不上就是有人在中間，請拒絕        │
│                                        │
│  [ 拒絕 ]  [ 只能看 ]  [ 可以控制 ]    │
└────────────────────────────────────────┘
```

**三條不變式，各配一個測試：**

1. **這個視窗絕不顯示主控端自己算出的 4 位數。** 顯示了，使用者會照抄而不問對方，核對變成自欺——option C 能成立的唯一前提就是主控端手上沒有答案。
2. **輸入錯誤直接拒絕連線**，不給「再試一次」。攻擊者只有 1/10000 的一發機會，給重試等於送他一萬次。
3. **「Alice」這個名字未經驗證**，只是對方自報的。文案用「Alice 想連進」而不是「來自 Alice 的請求」，避免讓它看起來像身分保證。

### 連上之後

`SharePanel` 的觀看者清單顯示每個人的名字、模式（唯讀／控制中）、收回控制權與踢出的按鈕。

分頁標題列掛一個**分享中的徽章**。這是安全需求不是裝飾：使用者必須隨時一眼看出有人在看自己的終端機。

## 觀看端

### 入口與連線

新分頁選單多一項「連線到同事的終端機」（`tabCatalog` 加一筆）。

輸入 6 位短碼 → mDNS 查詢。找到就連；**找不到時自動展開手動位址並說明原因**：

```
在這個網路上找不到這組編號。
可能已失效，或你們不在同一個網路。

請對方唸出他畫面上的位址：
[ 192.168.1.33:47823 ]
```

這正是計畫① spec 那條「找不到時 UI 必須明確告知並引導使用手動位址，不是無聲失敗或無限轉圈」的具體長相。

### 等待同意時

畫面顯示**自己算出的 4 位數**並提示「請把這組數字唸給對方」。

跟主控端相反：這邊**必須**顯示，因為那正是要唸出來的東西。（主控端不能顯示自己的，見上。）

### 獲准後：`remote-terminal` 新分頁型別

**不重用 `terminal` 型別。** 既有終端機分頁的整套邏輯都假設背後有本機 PTY session（cwd 追蹤、書籤、AI 面板注入、close guard、agent mission），遠端分頁一個都沒有。

**踩過的坑**：側邊欄的「Agent: xxx」分頁實際型別是 `terminal` 而非 `code-assistant`，型別判斷搞錯曾害整套分頁邏輯做錯。新型別必須在**所有**既有的型別分支上被明確處理，包含 close guard。

**唯讀模式**：分頁明確標示「唯讀」，且按鍵**根本不送出**（不是送了被伺服器拒絕）。伺服器端的 `may_send_input` 照樣在——兩層都要有：前端那層是給使用者的回饋，後端那層才是安全邊界。

**尺寸**：xterm 依主控端的 cols/rows 建立，自動縮字級塞進視窗，塞不下給捲軸。觀看端**永遠不會**觸發對方的 resize。

## 錯誤處理

`EndReason` 的每個值各對應一句人話，**不能有「未知錯誤」**：

| 後端 | 使用者看到 |
|---|---|
| `Denied` | 對方沒有同意這次連線 |
| `HostStoppedSharing` | 對方停止分享了 |
| `SessionClosed` | 那個終端機已經關閉 |
| `KickedByHost` | 對方結束了你的連線 |
| `InvalidCode` | 編號無效或已失效 |
| `VersionMismatch` | 兩邊的 AITerm 版本不同，請更新 |
| `SasCommitMismatch` | **驗證失敗，可能有人在中間攔截** |
| `SasHandshakeFailed` | 連線交握失敗，請重試 |

連線中斷時**保留最後畫面**供閱讀，不清空、不自動重連（短碼已作廢，重連無意義）。

## 測試

- **Vitest**：五個新元件各自的行為，mock IPC 呼叫，比照 `src/components/CloseConfirmDialog/index.test.tsx` 的寫法。
- **三條不變式各一個測試**：同意視窗不顯示主控端自己的碼、輸錯即拒不給重試、唯讀分頁不送按鍵。
- **`remote-terminal` 型別覆蓋**：一個測試掃過所有既有的型別分支，確認新型別都有被處理——防「Agent: xxx」那類坑。
- **mDNS**：找到一台、找不到、找到多台三種情境各一個測試（後兩者是行為契約，不是邊角）。
- **手動驗證**（自動化測不到）：兩台實機走完分享 → 連線 → 核對 → 接手打字 → 踢出的完整流程，並確認防火牆詢問時的實際行為。

## 已知限制

| 限制 | 說明 |
|---|---|
| 防火牆開啟時的行為**仍**未經實測 | 2026-08-27 的實機測試（macOS 主控端 ← Windows 觀看端）確認：**macOS 這端按下分享時沒有跳出任何防火牆詢問**——但那台機器的應用程式防火牆是**關閉**的（`socketfilterfw --getglobalstate` 回報 State = 0），所以這只證明「防火牆關著時不會被打擾」，沒有證明開著時會怎樣。面板上那則事前提醒因此仍是基於推理；第一次在防火牆開啟的機器上使用時要回頭確認文案對不對得上實際的系統詢問，以及「按拒絕」之後的失敗長什麼樣 |
| mDNS 在擋多播的網路上失效 | 靠手動位址退路救；若連直連都被防火牆擋則完全不通 |
| 同一組短碼被多台機器廣播 | 不猜，要求改用手動位址。機率是百萬分之一等級 |
| 名字未經驗證 | `display_name` 是對方自報的，UI 不能讓它看起來像身分保證 |
