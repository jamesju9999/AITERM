# 目標導航：畫面歷史、里程碑、建議綁定里程碑 設計

日期：2026-10-06
前置：`2026-10-06-ai-cli-suggestion-sidebar-design.md`（側欄）、同日的大目標與 AI 潤飾（分支 `feat/suggestion-goal`）。

## 定位

建議功能的角色是**導航員**：幫使用者一步步朝大目標推進。不是「預測使用者下一句會打什麼」——那件事
Claude Code 內建的提示詞建議（重用完整對話與 prompt cache、成本低）做得比我們好，我們不比。

| | Claude Code 內建建議 | AITerm 建議（本設計之後） |
|---|---|---|
| 擅長 | 局部、最自然的下一步 | 長期、朝目標推進、一次多個選項 |
| 知道目標 | 否 | 是 |
| 知道進度 | 是（完整對話） | 里程碑＋畫面歷史 |
| 適用工具 | 只有 Claude Code | claude、codex、gemini… |

**現況的弱點**：AITerm 只讀終端機目前那一屏（約 40–60 行，遠小於 8000 字上限），看不到之前做了什麼，
所以「往目標推進」其實做不好，容易重複建議已完成的事。本設計補上這一塊。

## 三步走與關卡

每一步都能獨立發布、獨立有價值。**每一步做完要有驗收關卡**，通過才做下一步：

| 步驟 | 內容 | 關卡（使用者實機判斷） |
|------|------|------------------------|
| 1 | 穩定畫面歷史 | 同一批真實工作畫面，加歷史前後各產生建議，盲測比較：重複建議已完成的事有沒有變少、有沒有更貼近目標 |
| 2 | 里程碑（AI 拆解＋手動勾選＋AI 提議勾選） | 拆出的里程碑是否合理可用、AI 提議的勾選是否可信（誤判率） |
| 3 | 建議綁定里程碑 | 建議是否明顯朝「下一個未完成里程碑」推進 |

關卡的存在是因為「目標／歷史／里程碑會讓建議更好」目前**只是推論，沒有任何量測**。關卡不通過就不往下做，
不為了做完計畫而硬做。

## 步驟 1：穩定畫面歷史

### 做什麼

偵測到 AI 命令列工具在跑時，每當終端機從忙碌轉為閒置（工具回完話、安靜下來），把當時那一屏存進一個
環狀緩衝區。產生建議時，把最近幾張「穩定畫面」連同目前畫面一起交給 AI。

選「穩定畫面」而不是讀整份捲動歷史，是因為 TUI 會不斷重畫旋轉動畫與進度行，捲動歷史全是重複畫面幀
（這也是現在 `serializeTerminal` 固定 `scrollback: 0` 的原因）。閒置時的那一屏是這一輪的「結論畫面」。

### 單元與位置

- `src/lib/screenHistory.ts`（純函式，無 React）：
  - `normalizeScreen(raw)`：去 ANSI（沿用 `stripAnsiCodes`）、行尾空白 trim、收斂連續重複行
    （沿用 `collapseConsecutiveDuplicateLines`）、去掉前後空行。
  - `isSameScreen(a, b)`：新畫面的非空行中，**≥ 70% 出現在上一張**就視為同一畫面的重繪／小更新。
  - `pushScreen(history, screen)`：先 normalize；空白丟棄；與最後一張 `isSameScreen` 則**替換**最後一張
    （保留較新的），否則新增；超過 `MAX_SCREENS`（10）或總字元超過 `MAX_HISTORY_CHARS`（24000）就從最舊的丟。
  - `formatHistoryForPrompt(history, current, budget)`：舊→新排列，總字元不超過 `budget`（12000），
    超過時先丟最舊的；`current` 永遠保留。
- `useScreenHistory(sessionId, aiCliRunning, getIdleMs)`（`src/components/SuggestionSidebar/`）：
  掛在 **`TerminalView`**，不是側欄元件——側欄關著也要持續記錄。內部用輪詢（沿用 1 秒、`IDLE_MS` 2 秒的慣例），
  偵測「忙→閒」那一下就 `serializeTerminal` → `pushScreen`。回傳 `getHistory()`（讀 ref，不觸發重繪）。
- `PromptSuggestions` 新增 `getHistory?: () => string[]` prop；`buildSuggestionRequest` 新增參數接收
  已格式化的歷史；歷史為空時請求內容與現在完全相同。

### 提示詞

在「終端機畫面」之前加一節「較早的畫面（舊→新，用來判斷已經做過什麼）」，並要求：已完成的事不要再建議。

### 生命週期與隱私

- 只在偵測到 AI 工具執行中才記錄；工具結束、分頁關閉就清空。
- **只放記憶體，不寫磁碟、不持久化**：畫面可能含機敏內容。
- 畫面內容送往使用者設定的 AI 供應商——這與現況相同，但量變大。側欄的說明文字要明講
  「會把最近幾屏終端機內容送給你設定的 AI 供應商」。

### 成本

單次請求輸入從約一屏增加到最多約 12000 字元。自動模式每次都會付這個成本。側欄的「自動」開關提示文字要註明
「每次產生會用掉較多額度」。

### 風險

- 開側欄之前的歷史只有「偵測到工具之後」的畫面；工具已在跑時才開啟 AITerm 的情況沒有更早的資料。
- 「忙→閒」的判斷用輸出安靜 2 秒，Claude 思考時若安靜超過 2 秒會被誤判為閒置而多存一張半成品畫面；
  `isSameScreen` 會把它與之後的完成畫面合併，影響有限，但實機要看。
- 70% 重疊的門檻是經驗值，要用真實畫面調。

### 測試

`screenHistory` 的每個函式都要有「測資能區分對錯」的測試（例如：重疊 69% 與 71% 的兩組畫面分別落在門檻兩側；
上限剛好等於與多一字元）。`useScreenHistory`：忙→閒才記錄、工具沒在跑不記錄、工具結束清空、卸載清除計時器。
`PromptSuggestions`：有歷史時請求含歷史、無歷史時與現在位元組相同。突變驗證：拿掉去重、拿掉總量上限、
拿掉「只在偵測到工具時記錄」，測試都必須轉紅。

## 步驟 2：里程碑

### 資料

`Tab.suggestionMilestones?: { id: string; text: string; done: boolean }[]`，與 `suggestionGoal` 一起
持久化（`SavedTab`、`saveSessionTabs`／`restoreSessionTabs`）。上限 10 筆；每筆 `text` ≤ 120 字；`id` 為
`crypto.randomUUID()`。

### 功能

1. **AI 拆解**：目標存在時，目標區下方有「AI 拆解里程碑」。AI 回 JSON 字串陣列（5–8 筆，由大到小的先後順序），
   `parseMilestones` 負責容錯（code fence、前後雜訊、去重、截長、丟空）。結果顯示為可編輯清單，使用者**確認後**才寫入。
   已有里程碑時重新拆解需確認；**已完成的項目保留**，其餘由新結果取代。
2. **手動維護**：新增、編輯文字、刪除、勾選完成；順序可上下移。
3. **AI 提議勾選**（「檢查進度」按鈕，**使用者觸發，不自動**）：AI 依歷史＋目前畫面回
   `{ "done": ["<id>", …], "note": "一句話理由" }`，UI 顯示「AI 認為已完成：…」與每項的 [採用] [略過]。
   絕不自動打勾——誤判會累積，而且使用者看不到。
4. **目標改變**：不刪里程碑；清單上方顯示「目標已變更，要重新拆解嗎？」。
5. **進度**：標題旁顯示 `已完成/總數`。

### 單元

- `src/lib/milestones.ts`：型別、`parseMilestones`、`buildMilestonePlanRequest(goal, lang)`、
  `buildMilestoneCheckRequest(goal, milestones, history, current, lang)`、`parseMilestoneCheck`（容錯；丟掉不存在的 id）、
  `mergePlanKeepingDone(existing, planned)`。
- `MilestoneList`（`SuggestionSidebar/`）：清單與編輯 UI，沿用目標區的視覺語言。
- `TerminalView`／`TerminalApp`：與 `suggestionGoal` 同樣的 prop／callback／持久化管線。

### 測試與突變

解析函式：標準、code fence、雜訊、重複、超長、不存在的 id。`mergePlanKeepingDone`：已完成項保留且不重複。
UI：確認前不寫入、AI 提議必須逐項採用才勾選、重新拆解不丟已完成。突變：自動打勾（拿掉「需確認」）、
合併時丟掉已完成，測試必須轉紅。

### 範圍外（本步驟不做）

AI 自動更新、背景自動勾選。

## 步驟 3：建議綁定里程碑

- **焦點里程碑**：預設為第一個未完成的；使用者可點某項設為焦點（只存在記憶體，重開回到預設）。
- 提示詞新增一節：目標、全部里程碑（含完成狀態）、**目前焦點里程碑**；要求每個建議都推進焦點里程碑，
  已完成的不要再建議。
- 畫面顯示焦點里程碑看起來已完成時，第一個建議應是「驗證／收尾」類；仍由使用者在「檢查進度」確認後才勾選。
- 全部里程碑完成：側欄顯示「全部里程碑已完成」，建議改為驗收與收尾類。
- 沒有里程碑時，行為與步驟 1（只有目標＋歷史）完全相同。
- 卡片上標示它對應哪個里程碑（一行小字），讓使用者看得出建議為何而來。

測試：有／無里程碑、全部完成、焦點切換時請求內容的差異；沒里程碑時請求與步驟 1 位元組相同。
突變：拿掉焦點、拿掉完成狀態，測試必須轉紅。

## 跨步驟事項

- **i18n**：zh-TW 與 en 同步補齊；`i18n.test` 的語系漂移檢查要過。
- **持久化**：沿用 `Tab` 欄位＋ `sessionTabs` 白名單；畫面歷史**不**持久化。
- **實機驗收**：用假的 `./claude` 腳本（印多屏、sleep）驗偵測與歷史；**每次 osascript 點擊前必須先確認前景是 AITerm**
  （先截圖看標題列、不對就停手，不盲點），這是上次點到別的應用程式後的規則。
- **自動檢查**：每一步結束前 `npx tsc -b`、`npm run test`、新增檔案 eslint 全過；全 repo 既有的 lint 錯誤不算。
- **Windows**：側欄寬度改變終端機寬度的縮放行為仍未在 Windows 驗證，沿用既有清單；本設計不新增縮放路徑。
- **其他 AI 工具**：codex、gemini 等的畫面格式與填入行為只在 Claude Code 上驗過，列為待實機確認。

## 明確不做

- 讀取 Claude Code 自己的對話記錄檔（只對單一工具有效，且一般分頁與記錄檔的對應未驗證）。
- 全自動維護的 AI 滾動摘要（錯誤會累積，使用者看不到）。
- 背景自動勾選里程碑。
- 與 Claude Code 內建建議比「猜下一句」。

## 未決

- 歷史張數（10）與總量上限（24000／12000）是估計值，要用真實畫面調整；若成本太高，步驟 1 的關卡可能要求縮小。
- 盲測比較由誰、用哪些畫面做：需要使用者提供 3–5 個真實工作情境（含目標與當時的終端機畫面）。
